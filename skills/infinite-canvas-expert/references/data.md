# 无限画布数据与可靠性手册（持久化 / 主题 / 缓存 / 协作）

## 原子写与静默数据丢失链

JSON 读-改-写的事故链（实际发生过的永久丢数据）：非原子写半截文件 → 读异常静默返回空默认 → 业务把空值写回覆盖原文件。

防线三层，缺一不可：
1. **原子写**：tmp + rename（同盘原子）；写 JSON 前先 stringify 校验。
2. **损坏隔离**：读取失败时原文件改名 `<name>.corrupt-<时间戳>` 保留 + 显式警告，绝不静默当空处理。
3. **空值永不写回**：读失败/读为空时不允许覆盖非空存量；哨兵值（如 `__QDMY_DISK_V1__`）是标记不是数据。

## 非幂等请求

- POST 超时 ≠ 上游没收到：非幂等方法不自动重发（视频生图重复扣费实例），重试白名单只含 GET/HEAD/OPTIONS；提交类超时改拿 task_id 轮询、5s 节流 + 连续失败判死的参数与证据 → 详见 network-api.md 四（[ic] 非幂等不重发）。状态落盘/重启标记中断见下节。

## 内存态任务落盘

常驻服务的任务队列放内存 = 重启即丢。落盘：原子写 JSON + TTL（24h）+ 条数上限 + 启动加载时标记中断。

## 缓存版本链（改了没生效三连）

1. `?v=` 只在启动时重写 → 打补丁不重启，浏览器拿旧脚本。静态资源版本号在启动钩子按文件 mtime 重写。
2. i18n/loader 自己硬编码 VERSION → 新文案永远不生效。同理交给启动钩子。
3. HTML 本身被浏览器缓存 → 部署后提醒 Ctrl+F5。
4. 版本号固定存 VERSION 文件，别用"当天日期"回退——每次冷启动 HTML 全 diff 是 git 噪音源。

## keepalive 64KB 上限

Chrome `fetch keepalive` 载荷 >64KB 直接抛 TypeError，且常被 catch 吞掉 = 关页保存静默失效。关页兜底载荷剔除日志类大字段（实测：载荷含 500 条生成日志超限）。双保险：`visibilitychange` + `pagehide`。

## 多标签/多人冲突

- 本窗有未保存改动且对方保存时：弹选择框（载入最新 / 保留当前），不静默覆盖。
- 接受远端版本后**撤销/重做栈全部清空**——只清一半会出现跨版本撤销串味。
- "冷却期内静默沿用上次决策"是坑：冲突弹窗 30 秒冷却期间新冲突静默按旧选择处理 → 静默覆盖。
- 独占锁防互踩：心跳 15s / TTL 45s（心跳停 45s 视为掉线释放）。React Flow 批量提交 → 详见 interaction.md 表单与字段映射。

## 数据只跟服务端走（Web 化桌面应用）

Tauri/Electron 前端 Web 化时，把 localStorage/sessionStorage/IndexedDB 整体替换为服务端 KV 垫片（`/api/kv`，key 校验拒 `..` + resolve 包含检查防越界），否则换设备/换浏览器必丢。两个坑：
- **同步路径预取**：bundle 可能同步读 localStorage，必须同步 XHR 预取，否则首帧读到 null 并把 null 写回（假 null 覆盖真数据）。
- **镜像目录别撞车**：自管同步镜像若写在 bundle 自己的“磁盘 localStorage”目录，bundle 启动清理会把镜像当垃圾删掉（实测启动 1 秒内 5 个文件被删）——镜像迁独立目录（data/lsSync/）+ 读侧取两处较新者自愈（commit c3750db）；lsSync 属主必须是容器用户（root 建目录写回静默失败）。

## 资源泄漏与请求纪律

- 节点编辑器整体替换数据（undo/远端同步）时，旧节点持有的重资源实例（播放器/编辑器/常驻 rAF 轮询）必须显式销毁——数组换了引用不等于实例死了。所有替换点走统一清扫函数。
- 所有 fetch 检查 `res.ok`——不检查时失败分支拿错误体当正常数据用（拿 file.name 冒充文件名实例）。
- 列表类字段加条数上限（消息/日志 200 条），防长会话无界增长。

## 主题系统（硬编码 !important 诊断法）

症状：改 CSS 变量主题不动。诊断：把全部变量设成刺眼色（如红），界面只有 ~2% 变色 = 主题是直写 `background: #xxx !important` 而非变量驱动。

修法（程序化生成覆盖层，别手写）：
1. 按感知亮度把底色中性化（r=g=b）；色通道极差 ≤40 判为底色中性化，>40 是语义色（成功/警告/危险）保留。
2. 亮度阶梯拉开层级：page → card 的相对亮度比要有阶梯（实例 1.041→1.178），否则整片黑没有层次。
3. 直写 `!important` 压不住变量的元素（html/body/shell 直钉背景）单独生成 surface 规则直钉。
4. 替换选择器时防污染：先判 `.theme-dark` 规则再处理 `:not(.theme-dark)`，否则浅色规则会漏进深色主题。
5. 多套主题切换逻辑并存时（主切换器 + 画布自己的 applyTheme），画布侧**镜像三态逻辑**而不是监听事件回写——回写会把第三态抹掉甚至无限递归。

## 回滚纪律

- 一次部署只带一件改动；出回归能立刻归因。三件一起上出回归 = 全退重做。
- 稳定基线 commit 明确标记（"稳定基线"），实验改动推备份分支，main 只进验证过的。
- 部署前后数据指纹比对（对象数 + 关键文件 md5）；备份目录按用途命名（`_backup_<用途>_<时间>`）。
